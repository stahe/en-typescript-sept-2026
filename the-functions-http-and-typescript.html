    12. The functions HTTP and TypeScript

    Here we present two ways to make HTTP requests in TypeScript: the [fetch] function, which has been native since Node 18, and the third-party library [axios]. The scripts for this chapter are located in the [http] folder of the project.

    12.1. Choosing Tools HTTP

    In 2019, fetch had not yet been implemented by node.js, and the original document recommended the <span style="color: #9a3412">node-fetch package. Since Node 18 (2022), fetch has been a native global function, standardized by the fetch standard—there is no longer a need to import it.

    [axios] remains an interesting library, however: compatible with both node.js and browsers, it offers a slightly richer API (interceptors, automatic JSON serialization, standardized error handling). We present both, using the same example, to show that the coding approach is similar.

    12.2. The Tax Calculation Server

    This chapter, like the following ones, refers to the tax calculation server PHP built in the course “Introduction to the PHP7 Language Through Examples.” Its installation (Laragon, NetBeans, config.json configuration) has not changed and is still described in this course PHP—we will not revisit it here.

    Reminder of the API hosted by this server:

    • [init-session] — GET main.php?action=init-session&type=x — sets the type (json, xml, html) of the desired responses; can be issued at any time;
    • [authentifier-utilisateur] — POST main.php?action=authenticate-user, posted parameters [user, password] — authorizes or denies the connection;
    • [calculer-impot] — POST main.php?action=calculate-tax, posted parameters [marié, enfants, salaire] — performs a tax calculation simulation;
    • [lister-simulations] — GET main.php?action=list-simulations — lists the simulations performed since the start of the session;
    • [supprimer-simulation] — GET main.php?action=delete-simulation&number=x — deletes a simulation from the list;
    • [fin-session] — ends the simulation session.
    Important: The scripts in this chapter assume that the server PHP is running locally on http://localhost/php7/scripts-web/impots/version-14/. In the environment where this document was prepared, this PHP server is not available: therefore, the executions below consistently show the “server not running” case (connection error), which is a real and verified result. The behavior in the event of success is described based on the code and comments, but could not be verified by an actual execution in this environment.

    12.3. [fetch-01] script

    This script uses [fetch] to initialize a JSON session with the tax calculation server:

      1  'use strict';
  2  
  3  // [mise à jour 2026] In 2019, you had to install the [node-fetch] package to have
  4  // the [fetch] function on the Node side. Since Node 18 (2022), [fetch] has been a
  5  // native global function, standardized by the "WHATWG Fetch standard": you no longer need to import it.
  6  // imports
  7  import qs from 'qs';
  8  import { sprintf } from 'sprintf-js';
  9  import moment from 'moment';
 10  
 11  
 12  // URL core of the tax calculation server
 13  const baseUrl: string = 'http://localhost/php7/scripts-web/impots/version-14/main.php?';
 14  // init session
 15  async function initSession(): Promise<any> {
 16    // [mise à jour 2026] The native [fetch] does not support the [timeout] option.
 17    // To limit the wait time, it is provided with a [signal] generated by
 18    // [AbortSignal.timeout(ms)] (available since Node 17.3): once this timeout has elapsed,
 19    // the query is automatically canceled and [fetch] raises an error.
 20    const options: RequestInit = {
 21      method: "GET",
 22      signal: AbortSignal.timeout(2000)
 23    };
 24    // Execution of the request HTTP [get /main.php?action=init-session&type=json]
 25    let débutFetch: moment.Moment | undefined;
 26    try {
 27      // asynchronous request—[fetch] returns a promise
 28      débutFetch = moment(Date.now());
 29      const response = await fetch(baseUrl + qs.stringify({
 30        action: 'init-session',
 31        type: 'x'
 32      }), options);
 33      // [response] is the entire response HTTP from the server (HTTP headers + the response itself)
 34      // We display this response to see its structure
 35      console.log(sprintf("réponse fetch formatée en json,=%j, %s", response, heure(débutFetch)));
 36      console.log("réponse fetch en javascript=", response);
 37      // The headers are HTTP
 38      console.log("entêtes de la réponse=", response.headers);
 39      // if the response is of type application/json, the server’s JSON response is retrieved using the asynchronous function [response.json()]
 40      // In this case, the calling code receives a [Promise] object
 41      // [await] allows you to retrieve the server’s response [json] rather than its promise
 42      const débutJson = moment(Date.now());
 43      const objet = await response.json();
 44      console.log(sprintf("réponse json=%j, type=%s, %s", objet, typeof (objet), heure(débutJson)));
 45      return objet;
 46      // If the response is of type text/plain, the server’s text response is obtained using [response.text()]
 47      // In this case, the calling code receives a [Promise] object
 48      // [await] allows you to retrieve the server’s response [texte] rather than its promise
 49      // const text = await response.text();
 50      // console.log("response text=", text);
 51      // return text;
 52    } catch (error: any) {
 53      // We're here because the server sent an error code [404 Not Found, ...] along with an empty body—we're displaying the error to see its structure
 54      // or because the client [fetch] threw an exception (network inaccessible, etc.)
 55      // the error structure is displayed
 56      console.log(sprintf("error fetch en json=%j, %s", error, heure(débutFetch)));
 57      console.log("error fetch en javascript=", typeof (error), error);
 58      // the received error message is logged
 59      throw error.message;
 60    }
 61  }
 62  
 63  // the main function executes the asynchronous function [initSession]
 64  async function main(): Promise<void> {
 65    try {
 66      console.log("requête HTTP vers le serveur en cours ---------------------------------------------");
 67      const response = await initSession();
 68      console.log("succès ---------------------------------------------");
 69      console.log("réponse=", response, typeof (response))
 70    } catch (error) {
 71      console.log("erreur ---------------------------------------------");
 72      console.log("erreur=", error, typeof (error));
 73    }
 74  }
 75  
 76  // test
 77  main();
 78  
 79  // utility to display time and duration
 80  function heure(début?: moment.Moment): string {
 81    // current time
 82    const now = moment(Date.now());
 83    // time formatting
 84    let result = "heure=" + now.format("HH:mm:ss:SSS");
 85    // Should a duration be calculated?
 86    if (début) {
 87      const durée = now.valueOf() - début.valueOf();
 88      const milliseconds = durée % 1000;
 89      const seconds = Math.floor(durée / 1000);
 90      // time and duration formatting
 91      result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
 92    }
 93    // result
 94    return result;
 95  }
    • Lines 3–5: [mise à jour 2026] — comment noting that fetch is now native, unlike in 2019;
    • line 18: AbortSignal.timeout(2000) — replaces the timeout option in <span style="color: #9a3412">node-fetch (which does not exist in native <span style="color: #9a3412">fetch): after 2 seconds, the request is automatically canceled;
    • line 27: fetch(URL, options) — the syntax remains that of standard fetch: a URL and an options object (method, cancellation signal, etc.);
    • line 38: await response.json() — extracts the JSON body from the response; this is itself an asynchronous operation (response may be a stream currently being received);
    • Line 50: <span style="color: #9a3412">fetch only throws an exception if the request HTTP failed (network unavailable, timeout, etc.). If a response is received—even with an error code (400, 500, etc.)—fetch does not throw an exception: the response is available as usual, line 38.

    12.4. script [fetch-02]

    12.5. script [axios-01]

    Same example, with [axios]:

      1  'use strict';
  2  import axios, { AxiosInstance, AxiosRequestConfig } from 'axios';
  3  
  4  // Axios default configuration
  5  axios.defaults.timeout = 2000;
  6  axios.defaults.baseURL = 'http://localhost/php7/scripts-web/impots/version-14';
  7  
  8  // init session
  9  async function initSession(axios: AxiosInstance): Promise<any> {
 10    // request options HHTP [get /main.php?action=init-session&type=json]
 11    const options: AxiosRequestConfig = {
 12      // [mise à jour TypeScript] axios.request() accepts, in terms of typing, only one
 13      // configuration argument: the URL must therefore appear in [options.url]
 14      // rather than as a separate first parameter of `request()`
 15      url: 'main.php',
 16      method: "GET",
 17      // parameters of URL
 18      params: {
 19        action: 'init-session',
 20        type: 'x'
 21      }
 22    };
 23    // execution of the request HTTP [get /main.php?action=init-session&type=json]
 24    try {
 25      // asynchronous request
 26      const response = await axios.request(options);
 27      // The response consists of the entire HTTP response from the server (HTTP headers + the response itself)
 28      // This response is displayed to view its structure
 29      console.log("réponse axios=", response);
 30      // The server's response is in [response.data]
 31      return response.data;
 32    } catch (error: any) {
 33      // We are here because the server sent an error code: [404 Not Found, 500 Internal Server Error, ...]
 34      // The parameter [error] is an exception instance—it can take various forms
 35      // It is displayed to show its structure
 36      console.log("axios error=", typeof (error), error);
 37      if (error.response) {
 38        // The server reported an error in the status HTTP, but it also sent a response
 39        // so this response is found in [error.response.data]
 40        // We know that the server sends responses jSON with the structure {action, status, response}
 41        // and that in the event of an error, the error message is in [réponse]
 42        return error.response.data;
 43      } else {
 44        // the error is triggered
 45        throw error;
 46      }
 47    }
 48  }
 49  
 50  // the `main` function executes the asynchronous function [initSession]
 51  async function main(): Promise<void> {
 52    try {
 53      console.log("requête HTTP vers le serveur en cours ---------------------------------------------");
 54      const response = await initSession(axios);
 55      console.log("succès ---------------------------------------------");
 56      console.log("réponse=", response, typeof (response))
 57    } catch (error: any) {
 58      console.log("erreur ---------------------------------------------");
 59      console.log("erreur=", error.message);
 60    }
 61  }
 62  
 63  // test
 64  main();
    • line 24: axios.request(options) — unlike <span style="color: #9a3412">fetch</span>, the URL and options are grouped into a single configuration object;
    • line 33: error.response — if the server responded (even with an error code), Axios places this response in error.response, which is accessible in the <span style="color: #9a3412">catch block — unlike <span style="color: #9a3412">fetch</span>, Axios always throws an exception whenever the status code is not a success (2xx);
    • line 26: the successful response is in response.data — axios automatically extracts JSON; there’s no need for a separate await response.json() as with fetch.

    12.6. [axios-03] script — authentication

    This script chains two requests: init-session, followed by user-authentication in [POST], with a body encoded by the [qs] library:

      1  'use strict';
  2  import axios, { AxiosInstance, AxiosRequestConfig } from 'axios';
  3  import qs from 'qs'
  4  
  5  // axios configuration
  6  axios.defaults.timeout = 2000;
  7  axios.defaults.baseURL = 'http://localhost/php7/scripts-web/impots/version-14';
  8  
  9  
 10  // session initialization
 11  async function initSession(axios: AxiosInstance): Promise<any> {
 12    // request options HHTP [get /main.php?action=init-session&type=json]
 13    const options: AxiosRequestConfig = {
 14      // [mise à jour TypeScript] URL included in [options.url] (The axios.request() type accepts only one argument)
 15      url: 'main.php',
 16      method: "GET",
 17      // parameters of URL
 18      params: {
 19        action: 'init-session',
 20        type: 'json'
 21      }
 22    };
 23    try {
 24      // execution of the query HTTP [get /main.php?action=init-session&type=json]
 25      const response = await axios.request(options);
 26      // The server's response is in [response.data]
 27      return response.data;
 28    } catch (error: any) {
 29      // server response
 30      if (error.response) {
 31        // The response jSON is in [error.response.data]
 32        return error.response.data;
 33      } else {
 34        // The error is retried
 35        throw error;
 36      }
 37    }
 38  }
 39  
 40  async function authentifierUtilisateur(axios: AxiosInstance, user: string, password: string): Promise<any> {
 41    // request options: HHTP [post /main.php?action=authentifier-utilisateur]
 42    const options: AxiosRequestConfig = {
 43      // [mise à jour TypeScript] URL included in [options.url]
 44      url: 'main.php',
 45      method: "POST",
 46      headers: {
 47        'Content-type': 'application/x-www-form-urlencoded',
 48      },
 49      // body of POST
 50      data: qs.stringify({
 51        user: user,
 52        password: password
 53      }),
 54      // parameters of URL
 55      params: {
 56        action: 'authentifier-utilisateur'
 57      }
 58    };
 59    try {
 60      // Execution of the request HTTP [get /main.php?action=init-session&type=json]
 61      const response = await axios.request(options);
 62      // The server's response is in [response.data]
 63      return response.data;
 64    } catch (error: any) {
 65      // server response
 66      if (error.response) {
 67        // The response jSON is in [error.response.data]
 68        return error.response.data;
 69      } else {
 70        // The error is re-triggered
 71        throw error;
 72      }
 73    }
 74  }
 75  
 76  // The `main` function executes the asynchronous functions one by one
 77  async function main(): Promise<void> {
 78    try {
 79      // init-session
 80      console.log("action init-session en cours ---------------------------------------------");
 81      const response1 = await initSession(axios);
 82      console.log("succès ---------------------------------------------");
 83      console.log("réponse=", response1);
 84      // authenticate-user
 85      console.log("action authentifier-utilisateur en cours ---------------------------------------------");
 86      const response2 = await authentifierUtilisateur(axios, 'admin', 'admin');
 87      console.log("succès ---------------------------------------------");
 88      console.log("réponse=", response2)
 89    } catch (error) {
 90      console.log("erreur ---------------------------------------------");
 91      console.log("erreur=", error);
 92    }
 93  }
 94  
 95  // test
 96  main();
    • Lines 39–53: The request POST sends its parameters (user, password) encoded as application/x-www-form-urlencoded via qs.stringify(...) in options.data;
    • Both functions are executed sequentially in main</span> (awaited one after the other): the second function only makes sense if the first one succeeded, since it depends on the session cookie set by <span style="color: #9a3412">init-session</span>.

    12.7. [axios-04] script — session cookie management

    This script refactors initSession and authentifierUtilisateur around a common function, [getRemoteData], which explicitly manages the session cookie PHP (PHPSESSID)—which is essential because the server associates authentication and simulations with a session HTTP:

    • getRemoteData adds the current session cookie (sessionCookie) to every outgoing request and updates this variable based on the Set-Cookie header of each received response—manually replicating what a browser would do automatically.

    12.8. [fetch-03] script — canceling requests

    [NOUVEAU depuis 2019] This script illustrates two uses of the fetch request cancellation mechanism, available natively since Node 18:

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU depuis 2019] native fetch + canceling a request HTTP
  4  // ========================================================================
  5  
  6  // [fetch] has been global since Node 18: the [node-fetch] package is no longer needed
  7  // used in 2019 in fetch-01.js/fetch-02.js (see the comments [mise à jour 2026]
  8  // added to these two files)
  9  
 10  // URL—the base file for the tax calculation server (see http/README.md)
 11  // As with axios-01.js, this script assumes that the PHP server for the exchange rate is running
 12  // locally: without it, requests fail with "fetch failed," which is normal
 13  const baseUrl: string = 'http://localhost/php7/scripts-web/impots/version-14/main.php';
 14  
 15  // Example 1: Request with maximum timeout using AbortSignal.timeout()
 16  async function requêteAvecDélaiMaximum(): Promise<void> {
 17    console.log("--- requête avec AbortSignal.timeout ---");
 18    try {
 19      const response = await fetch(baseUrl + '?action=init-session&type=json', {
 20        // After 2 seconds, the request is automatically canceled
 21        signal: AbortSignal.timeout(2000)
 22      });
 23      const données = await response.json();
 24      console.log("réponse =", données);
 25    } catch (erreur: any) {
 26      // if the server does not exist (which is likely in this exercise), or if the timeout is exceeded,
 27      // [erreur.name] is either "TimeoutError" or "AbortError," as appropriate
 28      console.log("erreur.name =", erreur.name, ", message =", erreur.message);
 29    }
 30  }
 31  
 32  // Example 2: Manual cancellation of a query, for example because
 33  // the user has changed their mind (e.g., they retype in a search field)
 34  async function requêteAnnulableManuellement(): Promise<void> {
 35    console.log("--- requête annulée manuellement ---");
 36    const contrôleur = new AbortController();
 37  
 38    // a "business logic" cancellation is scheduled after 500 ms
 39    // (in a real application, this would be, for example, clicking a “Cancel” button)
 40    setTimeout(() => {
 41      console.log("annulation manuelle déclenchée");
 42      contrôleur.abort();
 43    }, 500);
 44  
 45    try {
 46      const response = await fetch(baseUrl + '?action=init-session&type=json', {
 47        signal: contrôleur.signal
 48      });
 49      const données = await response.json();
 50      console.log("réponse =", données);
 51    } catch (erreur: any) {
 52      console.log("erreur.name =", erreur.name, ", message =", erreur.message);
 53    }
 54  }
 55  
 56  async function main(): Promise<void> {
 57    await requêteAvecDélaiMaximum();
 58    await requêteAnnulableManuellement();
 59  }
 60  
 61  main();
    • [AbortSignal.timeout(ms)]: automatically cancels the request if it exceeds the specified timeout—a pattern already seen in the fetch-01 script;
    • [AbortController]: allows for manual cancellation, triggered by any application event (here, a setTimeout simulating, for example, a click on a “Cancel” button, or new text entered in a search field that invalidates the previous query).
